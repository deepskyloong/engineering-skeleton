# Structure and placement

## Tree

```text
<project-name>/
├── README.md
├── AGENTS.md
├── docs/
│   ├── README.md
│   ├── charter.md
│   ├── structure.md
│   ├── conventions.md
│   └── committing.md
├── src/
├── tests/
└── <overlay files>
```

A monorepo replaces `src/` and `tests/` with `apps/` and `packages/`; each member carries its own `README.md`, `src/`, `tests/`, and `docs/` when it has member-specific facts. A single-package repository keeps `src/` and `tests/` at the root and does not fake a member level.

## Placement rules

1. Is it normative for this repository? → `docs/`.
2. Is it a copyable command or procedure someone runs under pressure? → `docs/operations/`.
3. Is it a fact a consumer may rely on across efforts? → `docs/contracts/`.
4. Is it a choice with rejected alternatives? → `docs/decisions/`.
5. Is it deferred? → `docs/backlog/`.
6. Is it a lesson that changes future behavior? → `docs/knowledge/`.
7. Is it configuration for a tool? → beside the code it configures.

## Artifact tiers

| Tier | Meaning | In git |
|---|---|---|
| Authoritative | Source of truth | Yes |
| Regenerable | Produced from an authoritative file by a command | No |
| Runtime | Caches, session state, run output | No |

Mark a regenerable file with `generated by <command> — do not edit` as its first line.
