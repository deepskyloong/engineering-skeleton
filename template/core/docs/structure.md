# Structure and placement

## Levels

A repository has three levels: root, member, module. The root holds the entry files (`README.md`, `AGENTS.md`), the shared vocabulary (`GLOSSARY.md`, and `GLOSSARY-MAP.md` when member vocabularies exist), the shared `docs/` and `work-packages/` trees, and the code boundary. A member is a package or app with its own `README.md`, `src/`, `tests/`, and docs when it has member-specific facts. A module is a boundary inside a member; it earns its own `AGENTS.md` only when it has rules that would be wrong at member level.

This template starts as a single-package repository: `src/` and `tests/` sit at the root. A monorepo replaces them with `apps/` and `packages/`; a single-package repository does not fake a member level.

## Directory ownership

Each directory's `README.md` lists its direct children. The docs index lists the role pages and any docs subdirectories; each subdirectory README lists its own pages. A parent above a directory lists directories, not files. No page restates another directory's inventory; a structure page that lists files is a second index.

## Placement rules

1. Is it normative for this repository? → `docs/`.
2. Is it a copyable command or procedure someone runs under pressure? → `docs/operations/`.
3. Is it a fact a consumer may rely on across efforts? → `docs/contracts/`.
4. Is it how the system is organized and what a change must respect? → `docs/architecture/`.
5. Is it a choice with rejected alternatives? → `docs/decisions/`.
6. Is it deferred? → `docs/backlog/`.
7. Is it a lesson that changes future behavior? → `docs/knowledge/`.
8. Is it configuration for a tool? → beside the code it configures.

The chosen home's `README.md` is the membership list. Do not add a row here.

## Artifact tiers

| Tier | Meaning | In git |
| --- | --- | --- |
| Authoritative | Source of truth | Yes |
| Regenerable | Produced from an authoritative file by a command | No |
| Runtime | Caches, session state, run output | No |
| Package evidence | A report, inventory, or reproduction script a work package owns and cites | Yes |

A review report body outside a work package is runtime; one inside a work package is package evidence. Mark a regenerable file with `generated by <command> — do not edit` as its first line.
